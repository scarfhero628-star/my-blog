새로운 프레임워크, 언어, 패러다임이 끊임없이 쏟아지는 개발 세계에서 **무엇을**, **어떻게** 공부할지 결정하는 것 자체가 하나의 능력입니다. 아무리 열심히 공부해도 방향이 잘못되면 시간이 낭비됩니다. 이 글에서는 수년간 검증된 개발자 학습 전략 7가지를 정리했습니다.

## 1. 배우는 것이 아니라 만드는 것으로 배워라

가장 흔한 실수는 튜토리얼을 처음부터 끝까지 따라가며 "이해했다"고 착각하는 것입니다. 진짜 학습은 **직접 무언가를 만들 때** 일어납니다.

```
❌ 잘못된 방식: 튜토리얼 → 강의 → 책 → 또 다른 튜토리얼
✅ 올바른 방식: 목표 프로젝트 설정 → 필요한 것만 찾아서 적용 → 완성
```

작은 프로젝트라도 좋습니다. Todo 앱, 날씨 앱, 개인 블로그처럼 이미 널리 만들어진 것도 직접 만들어보면 완전히 다른 학습 경험이 됩니다.

## 2. 파인만 기법으로 진짜 이해를 확인하라

노벨 물리학상 수상자 리처드 파인만의 학습법입니다. 개념을 배운 후 다음 단계를 따르세요.

1. **개념을 종이에 적는다** — 막힘 없이 설명할 수 있는지 확인
2. **모르는 부분을 찾는다** — 설명이 막히거나 흐릿한 부분
3. **원천 자료로 돌아간다** — 빈틈을 채운다
4. **다시 단순하게 설명한다** — 초등학생도 이해할 수 있을 정도로

개발로 적용하면: 배운 개념을 팀원이나 후배에게 설명해보거나, 블로그 글로 써보세요. 설명하다 막히는 부분이 바로 아직 모르는 부분입니다.

## 3. 간격 반복(Spaced Repetition)으로 기억을 굳혀라

사람의 뇌는 시간이 지남에 따라 정보를 잊어버립니다(에빙하우스 망각 곡선). 간격 반복은 잊기 직전에 복습해서 기억을 효율적으로 강화하는 방법입니다.

### 실용적인 도구

- **Anki** — 플래시카드 기반 간격 반복 앱. 코드 스니펫, 개념 정리에 탁월
- **Obsidian** — 마크다운 기반 노트. 연결 고리를 만들며 복습

```bash
# Anki 활용 예시: API 응답 코드를 카드로 만들기
앞면: HTTP 429 상태 코드의 의미는?
뒷면: Too Many Requests — 속도 제한 초과
```

## 4. 80/20 법칙을 적용하라

파레토 법칙에 따르면 결과의 80%는 원인의 20%에서 옵니다. 학습도 마찬가지입니다.

새 언어나 프레임워크를 배울 때 전체 기능의 **20%만 익혀도 실무의 80% 상황에 대응**할 수 있습니다. 예를 들어 Python을 배울 때:

- 자주 쓰는 자료구조 (리스트, 딕셔너리, 세트)
- 함수와 클래스 기본
- 파일 I/O와 예외 처리
- 자주 쓰는 표준 라이브러리 (os, json, re)

이 네 가지만 잘 알아도 웬만한 스크립트는 작성할 수 있습니다. 나머지는 필요할 때 찾아보면 됩니다.

## 5. 의도적 연습(Deliberate Practice)으로 약점을 공략하라

단순히 반복한다고 실력이 늘지는 않습니다. **의도적 연습**은 현재 수준보다 약간 더 어려운 목표에 집중하는 것입니다.

### h3 코딩 연습 플랫폼 활용법

| 플랫폼 | 추천 용도 |
|---|---|
| LeetCode | 알고리즘·자료구조 |
| Codewars | 짧은 문제로 언어 숙련 |
| Exercism | 멘토 코드 리뷰 포함 |
| Project Euler | 수학 기반 논리 문제 |

매일 30분, 한 문제씩 꾸준히 풀어보세요. 쉬운 문제를 많이 푸는 것보다 어려운 문제 하나를 끝까지 파헤치는 것이 훨씬 효과적입니다.

## 6. 공부한 내용을 즉시 코드로 옮겨라

개념을 읽고 이해한 것과 직접 코드로 구현하는 것은 다릅니다. 무언가를 배우면 바로 작은 예제 코드를 작성해보세요.

```javascript
// 배운 개념 → 즉시 실험
// 클로저를 배웠다면:
function makeCounter() {
  let count = 0;
  return () => ++count;
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
```

이렇게 코드로 확인하면 "알 것 같다"에서 "안다"로 넘어갑니다.

## 7. 학습 일지로 성장을 추적하라

매일 혹은 매주 짧게라도 **무엇을 배웠고, 어디서 막혔는지** 기록하세요. 이것만으로도 다음과 같은 효과를 얻을 수 있습니다.

- 같은 실수를 반복하지 않음
- 성장 궤적을 눈으로 확인 → 동기 유지
- 나중에 블로그나 포트폴리오 재료로 활용

형식은 자유롭습니다. Notion, 마크다운 파일, 종이 노트 무엇이든 상관없습니다. 중요한 건 **꾸준함**입니다.

---

## 마치며

개발자의 학습은 끝이 없습니다. 하지만 그렇기에 **어떻게 배우는지**를 아는 것이 무엇을 배우는지만큼 중요합니다. 위의 7가지 전략을 한꺼번에 적용할 필요는 없습니다. 오늘 당장 하나씩 시도해보고, 자신에게 맞는 방법을 찾아가세요.

가장 빠른 성장은 가장 많이 공부하는 것이 아니라, **가장 효율적으로 공부하는 것**에서 옵니다.
