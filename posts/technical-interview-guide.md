## 왜 기술 면접이 어려운가

기술 면접은 단순히 코딩 실력만 테스트하지 않는다. 문제 해결 능력, 커뮤니케이션, 설계 사고, 그리고 협업 태도까지 종합적으로 평가한다. 많은 개발자가 실무에서는 뛰어나지만 면접에서는 긴장하거나 준비 부족으로 좋은 결과를 얻지 못한다.

이 가이드는 코딩 테스트부터 시스템 디자인, 행동 면접까지 기술 면접의 전 단계를 체계적으로 준비하는 방법을 소개한다.

---

## 1단계: 코딩 테스트 준비

### 핵심 자료구조와 알고리즘

코딩 테스트에서 반드시 알아야 할 핵심 주제를 우선순위에 따라 정리한다.

**필수 자료구조:**
- 배열, 문자열
- 해시맵 / 해시셋
- 스택, 큐, 덱
- 연결 리스트
- 트리, 이진 탐색 트리
- 그래프
- 힙 (우선순위 큐)

**핵심 알고리즘:**
- 이진 탐색
- 투 포인터, 슬라이딩 윈도우
- BFS / DFS
- 동적 프로그래밍 (DP)
- 그리디 알고리즘
- 정렬 알고리즘

### 풀이 접근법: UEPR 프레임워크

좋은 코딩 면접 풀이는 단순히 답을 내는 것이 아니라 **사고 과정을 보여주는 것**이다.

```
U - Understand: 문제를 정확히 이해하고 엣지 케이스를 파악
E - Example: 직접 예시를 들어 문제를 구체화
P - Plan: 알고리즘과 자료구조를 선택하고 시간/공간 복잡도를 분석
R - Refine: 코드 작성 후 개선점을 논의
```

```javascript
// 예시: Two Sum 문제 풀이
// 주어진 배열에서 합이 target이 되는 두 수의 인덱스를 반환

function twoSum(nums, target) {
  // U: 중복 사용 불가, 정답은 하나만 존재한다고 가정
  // P: 해시맵으로 O(n) 시간에 해결
  const seen = new Map();

  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];

    if (seen.has(complement)) {
      return [seen.get(complement), i];
    }

    seen.set(nums[i], i);
  }

  return [];
}

// 시간 복잡도: O(n), 공간 복잡도: O(n)
```

### 꾸준한 연습 루틴 만들기

코딩 테스트는 감각이다. 꾸준히 연습해야 실력이 쌓인다.

- **LeetCode Easy** 문제를 하루 1~2개씩 꾸준히 풀기
- 한 문제를 풀었다면 **다른 사람의 풀이**를 반드시 보고 더 나은 접근법 학습
- 풀었던 문제를 **2~3일 후에 다시** 풀어서 복기
- 비슷한 패턴 문제를 묶어서 집중 훈련 (예: 슬라이딩 윈도우 문제만 10개)

## 2단계: 시스템 디자인 면접

시스템 디자인은 경력 2년 이상의 개발자에게 중요한 면접 항목이다. "URL 단축 서비스를 설계하라", "트위터를 설계하라"와 같은 오픈 엔디드 질문을 받게 된다.

### 시스템 디자인 접근 순서

```
1. 요구 사항 명확화 (5분)
   - 기능적 요구 사항 (무엇을 해야 하나?)
   - 비기능적 요구 사항 (규모, 가용성, 지연 시간)
   
2. 규모 추정 (3분)
   - DAU(일간 활성 사용자), TPS(초당 트랜잭션)
   - 저장 용량, 대역폭 추정

3. 고수준 설계 (10분)
   - 주요 컴포넌트를 그림으로 표현
   - API 엔드포인트 정의

4. 상세 설계 (15분)
   - 병목 지점 파악 및 최적화
   - 데이터베이스 스키마
   - 캐싱 전략, 샤딩 방법

5. 마무리 (5분)
   - 단일 장애 지점(SPOF) 논의
   - 모니터링 및 알림 방안
```

### 반드시 알아야 할 핵심 개념

**확장성:**
- 수평 확장 vs 수직 확장
- 로드 밸런서 (Round Robin, Least Connections)
- 데이터베이스 샤딩과 복제

**성능:**
- CDN을 통한 정적 자산 제공
- 캐싱 전략 (Redis, Memcached)
- 데이터베이스 인덱스와 쿼리 최적화

**안정성:**
- 서킷 브레이커 패턴
- 재시도 로직과 지수 백오프
- 메시지 큐 (Kafka, RabbitMQ)

## 3단계: 행동 면접 (Behavioral Interview)

기술 역량만큼 중요한 것이 행동 면접이다. 주로 "과거에 어떤 어려운 상황에서 어떻게 행동했는가"를 묻는다.

### STAR 방법론

```
S (Situation): 상황 설명
T (Task): 맡은 역할이나 해결해야 할 과제
A (Action): 내가 취한 구체적 행동
R (Result): 결과와 배운 점
```

### 자주 나오는 행동 면접 질문 유형

**갈등 상황:**
> "팀원과 기술적으로 의견이 충돌했던 경험을 말해 주세요."

**실패 경험:**
> "프로젝트에서 실수를 했던 경험과 어떻게 극복했는지 말해 주세요."

**리더십:**
> "다른 팀원들을 이끌거나 영향을 미쳤던 경험을 말해 주세요."

**자기 주도:**
> "상사의 지시 없이 스스로 주도적으로 문제를 해결했던 경험을 말해 주세요."

## 4단계: 면접 당일 준비

### 코딩 면접에서 말하는 습관 들이기

침묵은 금이 아니다. 면접관은 당신의 **사고 과정**을 듣고 싶어 한다.

- 문제를 받으면 바로 코딩하지 말고 큰 소리로 접근법을 설명
- 막히면 "지금 ○○ 방법을 생각하고 있는데 ○○ 경우를 처리하는 방법을 고민하고 있습니다"라고 말하기
- 코드를 작성하면서 무엇을 하고 있는지 설명
- 다 작성한 후 엣지 케이스와 복잡도를 스스로 분석

### 역질문 준비하기

면접 말미에 주어지는 역질문 시간도 중요하다. 준비된 질문은 관심과 성숙함을 보여준다.

**좋은 역질문 예시:**
- "이 팀에서 가장 어려운 기술적 도전은 무엇인가요?"
- "온보딩 과정은 어떻게 진행되나요?"
- "현재 팀의 개발 프로세스 중 개선하고 싶은 부분이 있나요?"
- "제가 성공적인 첫 90일을 보내려면 어떤 것에 집중하면 좋을까요?"

## 5단계: 준비 타임라인

면접까지 남은 시간에 따라 준비 전략이 달라진다.

### 1주일 전
- LeetCode Easy 문제 위주로 감각 되살리기
- 과거 프로젝트 경험 정리 및 STAR 방식으로 스토리 준비
- 지원 회사의 기술 스택과 제품 파악

### 1개월 전
- 핵심 알고리즘 패턴별 집중 연습
- 시스템 디자인 케이스 스터디 2~3개
- 모의 면접 1~2회 (동료 또는 온라인 플랫폼 활용)

### 3개월 전
- 체계적인 알고리즘 커리큘럼 완주
- 실제 프로젝트를 통해 취약한 기술 스택 보완
- 블로그 글쓰기나 오픈소스 기여로 포트폴리오 강화

## 마치며

기술 면접은 준비한 만큼 결과가 나온다. 하지만 한 번의 면접 결과가 당신의 역량 전부를 나타내지는 않는다. 떨어졌다면 무엇이 부족했는지 복기하고 다음 기회에 더 나은 모습을 보여 주면 된다.

꾸준한 연습, 체계적인 준비, 그리고 자신감이 합쳐질 때 좋은 결과를 얻을 수 있다. 지금 당장 시작하는 것이 가장 중요하다.
