## 왜 습관이 중요한가

프로그래밍은 지식의 축적이 아니라 **사고방식의 훈련**입니다. 매일 한 줄씩 쌓이는 습관은 1년 뒤, 3년 뒤 전혀 다른 개발자를 만들어냅니다. 화려한 사이드 프로젝트보다, 꾸준한 일상의 루틴이 실력 향상의 더 확실한 경로입니다.

이 글에서는 실제로 지속 가능하고, 효과가 검증된 7가지 습관을 소개합니다.

---

## 1. 아침마다 어제 코드 다시 읽기

하루를 시작할 때 전날 작성한 코드를 5~10분만 다시 읽어보세요. 이 간단한 습관이 주는 효과는 놀랍습니다.

- 어제는 괜찮아 보였던 변수명이 오늘은 어색하게 느껴집니다
- 중복 로직이나 불필요한 복잡도가 눈에 들어옵니다
- 리뷰 전에 스스로 코드를 다듬는 기회가 됩니다

어제의 자신이 첫 번째 코드 리뷰어가 되는 셈입니다.

---

## 2. 커밋 메시지를 제대로 쓰기

많은 개발자들이 `fix`, `update`, `asdf` 같은 커밋 메시지를 남깁니다. 하지만 좋은 커밋 메시지는 팀원과의 커뮤니케이션이자, 6개월 뒤 자신을 위한 편지입니다.

```
# 나쁜 예
git commit -m "fix bug"

# 좋은 예
git commit -m "fix: 로그인 후 리다이렉트 경로가 초기화되는 버그 수정

- useEffect 의존성 배열에서 router 객체 제거
- 관련 테스트 추가"
```

[Conventional Commits](https://www.conventionalcommits.org/) 스타일을 익혀두면 팀 프로젝트에서도 인정받을 수 있습니다.

---

## 3. 하루 15분, 문서 읽기

공식 문서를 읽는 습관은 의외로 드뭅니다. 대부분 Stack Overflow나 블로그에 의존하다 보니, 기능의 핵심보다는 해결책만 복사하게 됩니다.

매일 15분씩 사용 중인 라이브러리나 언어의 공식 문서를 읽어보세요. 예를 들어:

- MDN Web Docs의 JavaScript 레퍼런스
- React 공식 문서의 Hooks 섹션
- Node.js API 문서

처음엔 낯설지만, 3개월 후엔 다른 사람들이 모르는 기능을 자연스럽게 쓰고 있을 것입니다.

---

## 4. 에러 메시지를 정독하기

```bash
TypeError: Cannot read properties of undefined (reading 'map')
    at Dashboard (/src/components/Dashboard.jsx:23:20)
```

많은 개발자들이 에러를 보자마자 구글에 붙여 넣습니다. 하지만 에러 메시지 안에 이미 원인과 위치가 담겨 있는 경우가 대부분입니다.

에러를 만났을 때의 습관을 만들어보세요:
1. 에러 메시지 전체를 천천히 읽는다
2. 스택 트레이스에서 내 코드가 나오는 줄을 찾는다
3. 그 줄의 변수 상태를 확인한다

이 습관만으로도 디버깅 시간이 절반 이상 줄어듭니다.

---

## 5. 매주 하나의 개념을 깊게 파기

넓게 아는 것보다 좁게 깊이 아는 것이 실력의 척도입니다. 매주 하나의 개념을 골라 깊이 탐구해보세요.

### 예시 주제들

| 주차 | 주제 |
|------|------|
| 1주 | 이벤트 루프와 콜 스택 |
| 2주 | HTTP 캐싱 (ETag, Cache-Control) |
| 3주 | CSS Stacking Context |
| 4주 | 데이터베이스 인덱스 원리 |

핵심은 **왜(Why)** 를 이해하는 것입니다. 어떻게 쓰는지(How)는 문서가 알려주지만, 왜 그렇게 동작하는지는 직접 파야만 알 수 있습니다.

---

## 6. 작업 로그 남기기

하루를 마칠 때 그날 무엇을 했는지, 어떤 문제를 풀었는지 짧게 기록해두세요. 메모 앱, 노션, 마크다운 파일 어디든 상관없습니다.

```markdown
## 2026-09-06

### 한 일
- 로그인 폼 유효성 검사 로직 구현
- API 응답 타입 정의 (TypeScript)

### 막혔던 것
- CORS 설정 문제 → credentials: 'include' 추가로 해결

### 내일 할 것
- 단위 테스트 작성
- PR 올리기
```

이 로그는 성과 정리, 회고, 이직 준비 등 다양한 상황에서 강력한 무기가 됩니다.

---

## 7. 코드를 소리 내어 설명하기

이른바 **러버덕 디버깅(Rubber Duck Debugging)** 입니다. 문제를 혼자 해결하지 못할 때, 동료에게 설명하는 척 코드를 소리 내어 말해보세요.

말로 설명하려면 논리가 명확해야 합니다. 설명하다 보면 스스로 모순을 발견하는 경우가 많습니다. 실제로 이 기법은 많은 시니어 개발자들이 즐겨 사용합니다.

---

## 마치며

7가지 습관 중에서 지금 당장 하나만 고른다면, **커밋 메시지를 제대로 쓰기**를 추천합니다. 효과가 바로 보이고, 팀원들의 반응도 즉각적으로 느낄 수 있습니다.

습관은 거창하게 시작할 필요가 없습니다. 오늘 하루, 딱 하나만 실천해보세요.
