## 왜 습관이 실력을 결정할까?

개발 실력은 타고나는 것이 아니라 매일의 작은 행동이 쌓인 결과입니다. 수십 년 경력의 시니어 개발자와 이제 막 시작한 주니어 개발자의 차이는 대부분 **코딩 지식의 양**이 아니라 **습관의 질**에 있습니다. 이 글에서는 뛰어난 개발자들이 의식적으로 반복하는 7가지 습관을 정리했습니다.

---

## 1. 코드를 작성하기 전에 설계를 먼저 한다

많은 개발자가 문제를 받자마자 바로 코딩을 시작합니다. 하지만 시니어들은 **키보드를 두드리기 전에 생각을 먼저 정리**합니다.

- 해결해야 할 문제를 한 문장으로 요약한다
- 의사코드(pseudocode)나 간단한 다이어그램을 그린다
- 엣지 케이스(edge case)를 미리 나열한다

```
// 의사코드 예시: 사용자 목록 필터링
1. 입력: 사용자 배열, 필터 조건
2. 조건이 없으면 전체 배열 반환
3. 각 사용자를 순회하며 조건을 검사
4. 조건을 만족하는 사용자만 새 배열에 담아 반환
```

5분의 설계가 2시간의 디버깅을 아껴줍니다.

---

## 2. 커밋 메시지를 진지하게 쓴다

`git commit -m "fix"`처럼 무의미한 커밋 메시지를 남기는 것은 미래의 나(혹은 동료)에게 민폐입니다. 좋은 커밋 메시지는 **무엇을 바꿨는지**가 아니라 **왜 바꿨는지**를 설명합니다.

```bash
# 나쁜 예
git commit -m "수정"
git commit -m "버그 고침"

# 좋은 예
git commit -m "fix: 로그인 토큰 만료 시 무한 리다이렉트 방지"
git commit -m "feat: 사용자 검색에 페이지네이션 추가 (#142)"
```

Conventional Commits 컨벤션(`feat:`, `fix:`, `refactor:` 등)을 따르면 자동으로 변경 이력을 생성하거나 릴리스 노트를 작성하는 데도 유용합니다.

---

## 3. 매일 조금씩 리팩터링한다

보이스카우트 규칙(Boy Scout Rule)을 아시나요? **"캠프장을 처음보다 깨끗하게 남겨두어라."** 코드도 마찬가지입니다.

어떤 파일을 열었을 때 개선할 부분이 보인다면, 작업 범위 안에서 조금씩 정리합니다.

- 너무 긴 함수 → 작은 함수로 분리
- 의미 없는 변수명 → 명확한 이름으로 교체
- 중복 로직 → 공통 함수로 추출

한 번에 대규모 리팩터링을 하려 하면 실패하기 쉽습니다. 매일 5~10분씩 꾸준히 개선하는 것이 훨씬 효과적입니다.

---

## 4. 에러 메시지를 끝까지 읽는다

초보 개발자일수록 에러 메시지를 보자마자 스택 오버플로로 달려가는 경향이 있습니다. 하지만 대부분의 에러 메시지에는 이미 **원인과 해결 방향**이 담겨 있습니다.

```
TypeError: Cannot read properties of undefined (reading 'name')
    at getUserName (user.js:12:22)   ← 정확한 파일과 줄 번호
    at render (App.js:34:10)
```

에러 메시지 → 스택 트레이스 → 관련 코드 순으로 읽는 습관을 들이면 문제 해결 속도가 눈에 띄게 빨라집니다.

---

## 5. 문서를 읽는다 — 튜토리얼만 보지 않는다

유튜브 튜토리얼과 블로그 포스트는 시작하기에는 좋지만, 깊이에는 한계가 있습니다. 시니어 개발자들은 **공식 문서(Official Documentation)를 직접 읽는 습관**이 있습니다.

공식 문서를 읽으면:
- 최신 API와 베스트 프랙티스를 정확히 파악할 수 있다
- 튜토리얼에서 생략된 중요한 옵션이나 경고를 발견할 수 있다
- 라이브러리 내부 동작 방식을 이해하게 된다

처음에는 어렵게 느껴지지만, 익숙해질수록 문서가 가장 빠른 학습 자료가 됩니다.

---

## 6. 코드 리뷰를 배움의 기회로 삼는다

코드 리뷰에서 받은 코멘트를 단순히 "지적"으로 받아들이면 방어적이 됩니다. 대신 **"왜 이렇게 작성하는 게 더 나은가?"**를 이해하려는 자세가 중요합니다.

리뷰어 입장에서도 마찬가지입니다. 단순히 틀린 것을 지적하는 것이 아니라, 더 나은 방법을 제안하고 이유를 설명하면 팀 전체의 실력이 올라갑니다.

> 좋은 코드 리뷰는 코드를 고치는 것이 아니라 사람을 성장시킵니다.

---

## 7. 일과 후 완전히 쉰다

마지막 습관은 의외로 **쉬는 것**입니다. 번아웃은 실력 성장을 방해하는 가장 큰 적입니다.

시니어 개발자들은 퇴근 후에는 코드에서 완전히 벗어나 재충전합니다. 산책, 독서, 운동, 요리 — 무엇이든 좋습니다. 뇌가 충분히 쉬어야 다음 날 더 창의적인 문제 해결이 가능합니다.

---

## 마치며

이 7가지 습관은 하루아침에 생기지 않습니다. 하나씩 의식적으로 실천하다 보면 어느 순간 자연스럽게 몸에 배어있을 것입니다. 오늘부터 한 가지만 골라 시작해 보세요.
