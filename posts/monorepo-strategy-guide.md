## 모노레포란 무엇인가?

**모노레포(Monorepo)**는 여러 개의 프로젝트나 패키지를 하나의 Git 저장소에서 관리하는 방식입니다. 과거에는 서비스마다 별도의 저장소를 두는 **폴리레포(Polyrepo)** 방식이 일반적이었지만, 프로젝트 규모가 커지고 팀이 성장하면서 코드 공유와 일관된 설정 관리에 어려움이 생겼습니다.

Google, Meta, Microsoft 같은 대형 기술 기업들이 오래전부터 모노레포를 채택해 왔으며, 최근에는 Vercel의 Turborepo, Nx 같은 도구가 등장하면서 중소 규모 팀에서도 쉽게 도입할 수 있게 되었습니다.

## 모노레포의 장단점

### 장점

- **코드 재사용**: 공통 유틸리티, UI 컴포넌트, 타입 정의를 여러 앱에서 쉽게 공유할 수 있습니다.
- **일관된 설정**: ESLint, Prettier, TypeScript, 테스트 설정을 한 곳에서 관리해 팀 전체에 동일하게 적용됩니다.
- **원자적 커밋**: 여러 패키지에 걸친 변경 사항을 하나의 커밋으로 묶어 히스토리를 추적하기 쉽습니다.
- **빠른 피드백**: 의존하는 패키지를 로컬에서 바로 수정하고 결과를 확인할 수 있어 개발 속도가 향상됩니다.

### 단점

- **초기 설정 복잡성**: 워크스페이스 구성, 의존성 관리, 빌드 파이프라인 설계에 시간이 필요합니다.
- **CI 시간 증가**: 모든 패키지를 빌드·테스트하면 파이프라인이 느려질 수 있습니다 (캐싱으로 해결 가능).
- **저장소 크기**: 시간이 지날수록 저장소가 비대해질 수 있습니다.

## Turborepo 시작하기

Turborepo는 Vercel이 만든 고성능 모노레포 빌드 시스템으로, 빌드 캐싱과 병렬 실행을 통해 빌드 속도를 획기적으로 줄여줍니다.

### 1. 새 모노레포 생성

```bash
npx create-turbo@latest my-monorepo
cd my-monorepo
```

### 2. 기본 디렉터리 구조

```
my-monorepo/
├── apps/
│   ├── web/          # Next.js 웹 앱
│   └── docs/         # 문서 사이트
├── packages/
│   ├── ui/           # 공유 UI 컴포넌트
│   ├── config/       # 공유 설정 (ESLint, TS)
│   └── utils/        # 공통 유틸리티 함수
├── package.json
└── turbo.json
```

### 3. turbo.json 파이프라인 설정

```json
{
  "$schema": "https://turbo.build/schema.json",
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": [".next/**", "dist/**"]
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": []
    },
    "lint": {
      "outputs": []
    },
    "dev": {
      "cache": false,
      "persistent": true
    }
  }
}
```

`^build`는 "이 패키지가 의존하는 모든 패키지를 먼저 빌드하라"는 의미입니다. Turborepo는 이 의존 그래프를 분석해 병렬로 실행할 수 있는 작업을 동시에 처리합니다.

## 패키지 간 의존성 관리

공유 패키지를 각 앱에서 사용하려면 `package.json`에 워크스페이스 참조를 추가합니다.

```json
// apps/web/package.json
{
  "dependencies": {
    "@my-monorepo/ui": "*",
    "@my-monorepo/utils": "*"
  }
}
```

그런 다음 루트에서 의존성을 설치하면 됩니다.

```bash
npm install
```

패키지 매니저의 워크스페이스 기능(npm workspaces, yarn workspaces, pnpm workspaces)이 자동으로 심볼릭 링크를 생성해 로컬 패키지를 연결합니다.

## 원격 캐싱으로 CI 속도 높이기

Turborepo의 강력한 기능 중 하나는 **원격 캐시(Remote Cache)**입니다. 빌드 결과물을 클라우드에 저장해 팀원 간, CI/CD 간 공유할 수 있습니다.

```bash
# Vercel 원격 캐시 연결
npx turbo login
npx turbo link
```

연결 후 CI에서 이전에 빌드한 결과를 재사용하므로, 변경되지 않은 패키지는 빌드를 완전히 건너뜁니다. 실제로 빌드 시간이 **70~90%** 단축되는 경우도 있습니다.

## 언제 모노레포를 도입해야 할까?

모노레포가 모든 프로젝트에 적합한 것은 아닙니다. 아래 상황이라면 적극적으로 검토해 보세요.

- **여러 앱이 동일한 컴포넌트나 유틸리티를 공유**할 때
- **팀이 커지면서 코드 표준 관리가 어려워질** 때
- **프론트엔드 + 백엔드 + 공유 타입을 함께 유지관리**해야 할 때
- **패키지 버전 동기화 문제가 자주 발생**할 때

반면 프로젝트가 완전히 독립적이거나, 팀이 매우 작고 코드 공유 필요성이 없다면 굳이 복잡성을 감수할 필요는 없습니다.

---

## 마치며

모노레포는 단순한 폴더 구조 변경이 아닌, **팀의 협업 방식과 개발 문화를 바꾸는 아키텍처 결정**입니다. Turborepo 덕분에 설정 부담이 크게 줄었지만, 도입 전에 팀의 규모와 프로젝트 성격을 충분히 고려하는 것이 중요합니다. 작은 규모로 시작해 점진적으로 패키지를 분리해 나가는 접근법을 추천합니다.
